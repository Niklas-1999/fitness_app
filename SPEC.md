# SPEC: IRONCORE

Status: **approved by Niklas on 2026-10-31** (name, stats, ranks, streak rule, offline v1). Every training and nutrition rule refers to a section of [RESEARCH.md](RESEARCH.md).

## 1. Look and feel

- **Visual reference: Niklas's Cryptobro dashboard** (github.com/Niklas-1999/Cryptobro), copied 1:1 in spirit.
  - Near-black backgrounds tinted with the accent colour. No rounded corners anywhere: chamfered/clipped panel corners with neon corner brackets and a diagonal cut line.
  - Fonts: **Orbitron** (headings), **Rajdhani** (body), **Share Tech Mono** (numbers and labels). All are SIL Open Font License and bundled in the app.
  - Panel headers: an ID tag (`01`), a `SNAKE_CASE` title, a dashed underline with a scanning light, and mono meta text on the right.
  - Global effects: scanlines, vignette, a slow sweep band, the synthwave sun with a perspective grid and floating dust/data rain in the background, glitch text on titles, blinking cursors, and green/red flash on value changes.
  - **Boot sequence** at app start: a log of system lines plus a progress bar (tap to skip).
- **Theme engine (ported from Cryptobro `theme.js`):** the whole palette (backgrounds, tints, text shades, glows, background FX) is derived from **one accent colour**. Cryptobro's presets plus a custom colour (hex or picker). Changes apply live. Default: Cryptobro red `#FF1744`.
- **Sound:** short synthesized UI sounds in a **hacker/terminal style, not cheerful RPG**: keystroke clicks, data chirps, packet bursts, sub-bass hits, bit-crushed glitch stutters. They are original, generated by `tools/gen_sfx.py`. Can be switched off.
- **Haptics:** a light tick on taps, a heavy pulse on quest complete and level up.
- **Juice:** XP bars fill with a shine sweep, numbers count up, stat points fly into the stat panel, the level-up is a **terminal "PATCH_INSTALLER" sequence** (glitch-in, typed log, glitched level number, attribute changes since the last level-up, rank progress), and quests flash a "COMPLETE" stamp.

## 2. Onboarding: "SYSTEM INITIALIZATION"

Shown as a terminal dialogue, one question per screen, with a progress bar.

1. **Identity:** handle (display name).
2. **Biometrics:** age (18+ only, because the nutrition maths uses adult EFSA values), sex (used by the BMR formula; there is an option that uses the average of both constants), height, weight.
3. **Daily activity level** (excluding planned workouts at first; corrected adaptively later): 4 choices mapped to EFSA PAL 1.4/1.6/1.8/2.0 (R§9).
4. **Training experience:** none / <6 months / 6–24 months / >2 years → novice / novice / intermediate / advanced (ACSM, R§1).
5. **Health check:** 7 yes/no questions paraphrased from PAR-Q+ (R§8). Any YES → a notice to get medical clearance, then **conservative mode**.
6. **Primary goal:** lose fat · build muscle · get stronger · endurance (run 5 km) · general fitness. Optional secondary goal.
7. **Target:** target weight for fat loss or muscle gain. The app checks it is realistic and shows the weekly rate.
8. **Intensity:** GENTLE / STANDARD / HARD. This sets the weight-change rate (R§10), starting sets, and how close to failure the targets go.
9. **Schedule:** sessions per week and the exact weekdays, plus preferred session length (≈20 / 40 / 60 min).
10. **Equipment** (multi-select): none (bodyweight) · pull-up bar · resistance bands · dumbbells (max weight) · kettlebell · bench · full gym.
11. **Calibration test ("SYSTEM SCAN"):** max push-ups in any variation you can do, bodyweight squats (capped at 50), plank hold in seconds, and optionally pull-ups or rows. Gym users get calibration sets in their first session instead ("find a weight you can do 10 reps with, 2–3 left in the tank").

Result: a **STATUS REPORT** screen showing starting stats, rank, the generated plan, and **projections** (§5).

## 3. Plan generator

- **Split from the days per week** (ACSM R§1): 2–3 days → full body · 4 days → upper/lower · 5–6 days → upper/lower plus conditioning/mobility days. Novices are capped at 3 hard resistance days; extra days become cardio/mobility.
- **Each session:** warm-up quest → 4–6 main exercise quests (large before small, multi-joint first) → optional finisher (core/cardio).
- **Rep ranges by goal:** strength 6–10 (gym) · muscle 8–12 · endurance/general 10–15+ · bodyweight 8–15, then move up a variation.
- **Sets:** start at 1–3 per exercise by experience and intensity (R§1), and build toward ~10 sets per muscle per week for muscle goals (R§2).
- **Exercise library:** a curated set of real exercises with tags (muscle groups, equipment, movement pattern) and **progression ladders**, for example:
  - Push: wall → incline → knee → full → decline → archer push-up (+ dumbbell/bench press in a gym)
  - Squat: box/assisted squat → bodyweight squat → split squat → Bulgarian split squat → shrimp/pistol progressions (+ goblet/back squat)
  - Hinge: glute bridge → single-leg glute bridge → hip thrust (+ Romanian deadlift)
  - Pull: table/towel rows → inverted rows → negative pull-ups → pull-ups (+ dumbbell row / lat pulldown)
  - Core: dead bug → plank → side plank → hollow hold → leg raises
  - Cardio: Couch-to-5K intervals (R§7), brisk walking minutes
  - 65+ users: balance quests 3×/week (R§6)
- **Endurance goal:** Couch-to-5K schedule (9 weeks at 3 runs/week; stretched if fewer run days).
- **Weekly side quest:** reach 150 active minutes (WHO, R§6).

## 4. Daily loop: quests and progression

- On a training day the **DAILY DIRECTIVE** lists that day's quests, e.g. "PUSH-UP // 3 × 8", "PLANK // 3 × 30 s", "RUN/WALK // WEEK 2".
- Quest flow: start → optional rest timer between sets → done → rate it: **EASY / SOLID / HARD / FAILED** (an RIR proxy, R§4).
- **Progression per exercise, per session** (so it gets a bit harder each time, not on a fixed daily schedule):
  - All sets done and rated EASY/SOLID → next time +1 rep per set (or +5 s for holds).
  - At the top of the rep range in two consecutive sessions → **next variation** (bodyweight) or **+2–10% load** (weights), then reset to the bottom of the range (ACSM rule, R§1).
  - HARD → keep the same target. FAILED → repeat; two FAILED in a row → −10% reps or load.
  - A **deload week** every ~6th week, or early when HARD/FAILED ratings pile up (R§5).
- **Daily reroll:** once per day, one strength quest of the directive can be swapped. The replacement is another exercise of the same movement pattern your equipment allows (e.g. push-ups ↔ dumbbell press), otherwise a fresh exercise from the plan that wasn't trained in the last 48 h.
- **ARSENAL (QUESTS tab):** free training. Every exercise the equipment allows, grouped by movement, plus "cardio minutes", can be executed any day with normal XP and progression. Exercises outside the plan start from a calibrated state. The daily diminishing XP still applies (overtraining guard).
- **Non-training (rest) days** show a choice:
  - **REST PROTOCOL:** a one-tap check-in ("recovery logged"). It gives a small fixed XP (≈20, about a tenth of a training day) plus +1 VIT, and **keeps the streak alive**. Optional light extras for small XP: a walk (counts toward the WHO 150 min), stretching.
  - **TRAIN ANYWAY:** generates a **fitting extra session** that respects recovery. It trains muscle groups not hit in the last ~48 h, or does a light conditioning/mobility/core session. It never pushes progression on a muscle that is still recovering. Normal XP rules (incl. diminishing returns) apply.

## 5. Projections ("FORECAST")

- **Body weight:** a curve at the chosen weekly % rate (rates are a % of current weight, so it bends), with the ETA to the target weight. **Re-fitted weekly** from the logged weight trend (7-day average) and the logged intake. This is the adaptive TDEE (R§9).
- **Performance:** simulating the progression rules gives "≈ 3 × 12 full push-ups by week N", "first pull-up ≈ week N", "5 km run in ≈ 9 weeks". Each forecast assumes realistic success rates and is labelled "projection".
- **No kg-of-muscle predictions.** The evidence is too variable (RESEARCH "Not used").

## 6. RPG layer

- **XP per quest:** base ≈30 (scaled by quest size/difficulty) × a **daily diminishing multiplier** for the k-th quest of the day: 1.0, 1.0, 1.0, 0.9, 0.8, 0.6, 0.3, 0.15, then 0.05 for every quest after that. Doing more than a normal session barely pays, which **discourages overtraining** (5 quests ≈ 181 XP, 8 ≈ 212, 12 ≈ 218).
- Base XP per quest: strength/hold = 20 + 5 × sets, C25K run = 45, walk = minutes (10–45). Rating multiplier: EASY/SOLID ×1.0, HARD ×1.1, FAILED ×0.5 (showing up counts).
- **DIRECTIVE CLEAR** bonus +40 XP once per day. Streak multiplier +2% per streak day, capped at +30%.
- **Levels (no max level):** XP from L to L+1 = `max(60, round(84 · 1.075^L − 10))`. Simulated in `tools/level_curve.py`. With 4 sessions/week:

  | When | Level | Pace |
  |---|---|---|
  | Day 1 | 3 | 2 level-ups on day one |
  | Week 1 | ~8 | about 1 per training day |
  | Month 1 | ~21 | about 1 every other training day around L20 |
  | Month 2–3 | ~29–34 | about 1 per week around L30 |
  | Year 1 | ~52 | exponential: L40 ≈ 10 days, L50 ≈ 3 weeks, L75+ months |
- **Stats** (5, shown as a pentagon radar plus bars). Each completed quest gives +1 data point to its attribute (none on FAILED). An attribute rises by 1 after `max(2, value/4)` points, so early gains come quickly and later ones slowly. WIL gets a point for the first activity of the day and for a directive clear, and VIT for the rest check-in (and nutrition targets from P3):
  - **STR** strength: resistance quests
  - **END** endurance: cardio, high-rep and timed quests
  - **AGI** agility: mobility, core and balance quests
  - **VIT** vitality: daily nutrition, protein and water targets hit
  - **WIL** willpower: streak days and directive clears
- **Ranks:** GHOST L1 · RUNNER L10 · OPERATIVE L22 · ENFORCER L33 · VANGUARD L40 · APEX L46 · **LEGEND L53**. LEGEND takes **about one year** of consistent training (simulated: 351 days at 4×/week, 289 at 5×, about 15 months at 3×).
- **Streak:** +1 for every day with **at least 1 quest completed** (training days) or a **REST PROTOCOL check-in / any quest** (rest days). A day with neither **resets the streak to 0**. That is the only penalty.
- **Achievements** (e.g. first directive, 7/30/100-day streak, first full push-up, first pull-up, 5 km, levels, nutrition streaks) unlock **cosmetics**: avatar frames, banners, titles under the name, name-glitch effects, panel border styles.
- **Profile:** handle, avatar picture and banner (from the gallery via the system photo picker, so no permission is needed), equipped title, frame and banner, stats radar, records, achievement grid.

## 7. Nutrition: "FUEL"

- **Daily targets** (R§9–11): kcal from Mifflin BMR × PAL ± the goal adjustment (never below BMR), protein 1.6 or 2.0 g/kg, fat 30% of energy, carbs as the rest, fibre 25 g, water 2.0/2.5 L, plus EU reference values for sugar and salt shown for information.
- **Logging:**
  - **Scan an EU nutrition label** with the camera → offline OCR → parses kcal, fat, saturates, carbs, sugars, protein, salt (+ fibre) per 100 g → "I ate **[ 200 ] g**" or "whole package (g)". The food is saved to "my foods" for one-tap re-logging. The user always confirms or edits the parsed values first.
  - Manual entry, recent foods, favourites, edit/delete entries.
- **UI:** macro rings or bars that fill (cyberpunk gauges), with remaining kcal as a big counter. A daily VIT reward when targets are met.
- **Water:** +250/+500 ml buttons against the EFSA target.
- **Rewards:** reaching the protein target (+15 XP) and the water target (+10 XP) each give +1 VIT point once per day.
- **Body-weight log:** feeds the adaptive TDEE and the forecast. The trend line is an exponential moving average.
- **Adaptive TDEE:** after ≥14 days with ≥10 food-logged days and ≥4 weigh-ins, observed TDEE = average intake − (least-squares weight slope × 7700 kcal/kg). It is blended with the formula by coverage (full weight at 21 logged days) and clamped to 60–160 % of the formula. Targets then use the measured TDEE and the trend weight.

## 8. Data, privacy, platform

- Kotlin + Jetpack Compose, **Room** with real migrations, DataStore for settings, CameraX for the label scanner, Tesseract4Android OCR (offline). Min Android 8.0.
- **No INTERNET permission** in v1. All data stays on the phone. **Export/import** as a JSON file through the system file picker.
- Reminders: local notifications on training days (optional).

## 9. Later: online features (not in v1, decided 2026-10-31)

The **cloud sync, leaderboard and friends list** need a server, so the app would need the INTERNET permission. That breaks the "100% offline" rule from the handoff. Proposal: v1 stays offline. Later, add an **opt-in sync module** against a server Niklas controls (for example a small self-hosted backend). It would be off by default, with no Google services, and the local DB stays the source of truth.
